# 可复现材料、隐私与清理

## 应进入 Git 的小文件

- 本 Skill 的 SKILL.md、references、模板、构建脚本、C 探针源码、精确内核兼容补丁、profile 锁定 URL/SHA、自动测试。
- 上游许可声明；MIT 的 kwg 与 GPL v2 的内核补丁分别保留许可。
- 脱敏的历史验证结论和明确的待验证项。

## 不提交

私钥/预共享密钥/实际客户端配置、设备账号、完整序列号、实际 VPN 服务端地址、原始设备日志、完整内核导出地址表、用户资源、下载的上游包/源码大包、工具链、编译产物和测试夹具。它们放到被忽略的 build/，敏感内容设目录 0700、文件 0600。不要为了让 Git 干净而强制提交这些文件。

渲染的 app overlay 可含用户明确授权复制的客户端配置；导入成功后，既删除设备 USB 可见副本，也删除**本次生成的本机 staging 副本**。不要删除用户提供的原始配置文件。私钥禁止进入共享测试镜像/构建上下文。

## 清理顺序

1. 确认运行所需源码已纳入版本控制；先查看 git status，保护无关修改。
2. 将已验证的小型模块/helper、构建 manifest、source-compat.patch、必要设备快照和结果，按白名单压成**本地私有恢复包**。不把客户端私钥打进去。记录每个文件 SHA 和恢复包 SHA，再实际读回压缩包逐项校验。
3. 保留官方 Release ZIP（约 1.5 MB）即可，不必同时保留多份解压的 3.5 MB 二进制。构建出的 tun.ko/helper 合计约 50 KB，保留这些比下次重新编译省事，但只能用于指纹匹配的同一 profile。
4. 删除本轮可重新获取的源码包、解压目录、kernel-build、module 对象文件及成功测试的 mock-tests 目录。目标必须显式列出并确认在自己的工作目录内；不要模糊递归清理整个用户目录。
5. 运行 df/du，分别报告“删除文件的体积”和“当前可用空间”。APFS 快照、压缩/共享块和并发写入会让两者不同，不夸大实际释放量。
6. 最后检查 Git：只提交相关代码/文档；上游源码 clone 应恢复干净。提交不等于推送，未推送要说明。

不要全局 `docker system prune`、删除现有 Docker VM/镜像/卷或 Time Machine 快照。先分清哪些由本任务创建；本流程复用已有镜像时，就没有理由把其他项目镜像当“中间文件”删除。新测试容器用 --rm，成功的测试夹具自动删除。

## 不要清理 Kindle 的运行依赖

这些不是中间文件：

- `koreader/plugins/kwg.koplugin/`：原版二进制、插件、按需加载包装和 watchdog。
- `kwg-tun/`：重启后还需要的模块、探针、校验加载脚本。
- `kwg-service/`：手动控制、状态、自启动安装模板。
- 内部 `/var/local/kwg/`：真实配置、autostart 标记、状态和恢复保护。

只读 preflight 和临时安装诊断入口可在验证并归档后单独清理，但必须先确认不再被运行脚本引用。不要把“临时加载的模块会在重启后消失”误解成“模块文件可以删掉”。
